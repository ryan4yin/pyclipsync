# Repository Agent Guide

`pyclipsync` is a single-file, standard-library-only Python daemon
(`pyclipsync.py`) that bridges the Wayland and X11 clipboards. It is packaged
with Nix (`flake.nix`, `nix/package.nix`) and runs as a systemd user service.

## Keep the two service definitions in sync

The systemd user unit is defined in **two** places and they must be changed
**together**:

- `pyclipsync.service` — the standalone unit for manual installs into
  `~/.config/systemd/user/`.
- `nix/home-module.nix` — the unit generated by the Home Manager module
  (`systemd.user.services.pyclipsync`).

Whenever you change `Unit`, `Service` or `Install` settings, update both files.
Keep the same `Type`, `Restart`, `RestartSec`, `TimeoutStopSec` and the same
`After` / `PartOf` / `WantedBy` values in both. Only `ExecStart` differs by
design: the standalone unit uses `%h/.local/bin/pyclipsync`, the Nix module
uses the store path of the packaged binary.

## Tests

```sh
python3 -m unittest discover -v
```

Unit tests run without a graphical session. The integration class in
`tests/test_sync.py` skips itself unless `DISPLAY`, `WAYLAND_DISPLAY` and
`wl-copy`/`wl-paste`/`xclip`/`clipnotify` are all available.

## Conventions

- Standard library only; no third-party Python dependencies.
- After editing Python, run `python3 -m py_compile pyclipsync.py tests/test_sync.py`.
- Keep the service change above in mind: a change to one unit file without the
  other is a bug.
